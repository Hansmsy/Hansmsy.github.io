EvoHarness-RL：关于智能体短期目标与长期目标的思考

论文原文：EvoHarness-RL

给 Agent 一本工作笔记之后，还需要教它何时读、何时写，以及如何让记录真正推动下一步行动。

读 EvoHarness-RL 时，最吸引我的想法，是给智能体配一本可以查阅和更新的“工作笔记”。长任务里，模型需要持续知道目标是什么、哪些信息已经确认、还有什么没有完成。把这些内容显式记录下来，是支持持续执行的一个直接切入点。

01一本笔记，三种信息

论文将外部工作空间组织成 BPE：Belief 保存当前环境状态，Progress 记录子目标与执行进度，Experience 保存跨任务复用的方法和教训。前两者主要服务于当前任务，后者可以跨任务积累。

BPE 工作空间及访问动作
部分记录什么接口
Belief已观察到的事实、对象状态与约束track 查询状态
Progress当前子目标、已完成与待完成事项commit 更新进度
Experience可复用的方法、失败教训recall 检索；note 留下线索

对电商来说，“这次预算是 500 元”和“组合购买时要核对总额”属于不同的信息：前者是本次约束，后者才可能成为通用经验。这个区分可以避免把一次性的需求固化为长期偏好。

02先学会接口，再学习调用时机

EvoHarness-RL 采用 SFT 冷启动 → on-policy GRPO。主实验的学生是 Qwen3-8B，教师是 Claude Opus 4.6。底层沿用 GRPO，重点在于动作空间、奖励设计和经验更新流程。

SFT：从成功轨迹学习下一步回复

教师实际进入环境执行任务，使用与学生相同的笔记接口。收集后保留成功轨迹，再拆成“当前输入 → 下一步回复”的监督样本。因此，训练覆盖业务操作，也覆盖查询状态、更新进度和检索经验的动作。

公开代码只对目标回复计算 SFT 损失；数据按完整任务划分训练集和验证集，避免同一轨迹的不同轮次泄漏到两边。成功也不代表过程最优：反复搜索但最终完成的轨迹，仍可能被保留。

GRPO：比较同一任务的不同执行方式

学生随后自行采样交互轨迹。每个任务生成一组 rollout，在组内比较奖励，计算相对优势，再更新策略。比如同一个选购任务，一条轨迹遗漏了规格，一条成功但重复搜索，另一条借助一次状态查询高效完成，它们应得到不同的学习信号。

业务动作与笔记动作共用交互预算。奖励除了任务结果与无效、重复动作惩罚，还加入成功门控的效率项，以及逐渐退火的探索项。

R = Rbase + λeff Reff + λdiv(u) RdivReff = 1[成功] × (Tmax − 总步数) / Tmax

以 20 步上限为例：成功且用了 10 步，效率项为 0.5；成功且用了 16 步，效率项为 0.2；失败时则为 0。一次查笔记如果能避免后面多次返工，就可能值得保留。

论文的探索项统计四种 BPE 动作的覆盖率，权重按余弦退火到零。我的理解是：早期先给新接口一些尝试机会，后期由任务收益和执行成本决定保留哪些调用。

Claude 在 RL 中：批次之间整理经验

学生执行一批任务时使用固定经验库，新的 notes 暂存。批次结束后，Claude 读取按任务类型组织的成功、失败动作摘要、notes 与旧经验，提出新增、修改、合并或删除等增量编辑。更新后的经验供下一批检索。

两种更新需要分开理解。GRPO 改变学生的参数；Claude 整理改变学生可读取的外部知识。经验编辑并不是直接给学生做新一轮 SFT，也不能当成每条轨迹的奖励评分。

经验整理有额外推理成本，一轮整理还可能包含多个模型调用。另一个边界是：成功判定随环境变化，ALFWorld 和 WebShop 可从环境取得结果，WebArena 的部分语义匹配使用 LLM judge。评估整体收益时，要把这些成本与成功率一起看。

03从当前任务，走向长期目标

我觉得这套思路很适合多轮电商场景。用户会补充信息、修改预算，也会暂时岔开话题。任务笔记可以帮助 Agent 在回答临时问题之后，继续推进原来的目标。

一个电商任务的笔记示意
目标
选出适合宿舍的咖啡机。
约束
预算 500 元；宿舍功率限制待确认。
进度
比较三个候选，排除一个超预算型号。
下一步
核对功率，再比较使用成本。

用户问“胶囊机是什么”，并不意味着选购任务结束；用户把预算提高到 800 元，则需要更新约束，并重新考虑受影响的候选。笔记的价值，要通过后续行动体现出来。

长期目标与 Experience 也需要区分。“购买前核对最终价格”是经验；“分阶段完成宿舍采购”是持续目标。后者还需要阶段计划、剩余预算、依赖关系和完成条件。把经验库接上 Agent，并不自动解决长期目标管理。

04给个人和群体定制笔记

沿着这个方向，我会把笔记分成三个范围。下面是应用设想，尚不是论文验证过的结论。

范围适合保存的内容电商例子
当前任务本次约束、候选比较、执行进度哪些商品已核对功率，哪些仍待确认
个人明确表达的长期目标、稳定偏好及变化宿舍采购计划、已确认的功率限制
群体共性关注点、选购流程和适用经验宿舍用户通常需要先确认空间和功率

个人笔记帮助跨会话延续目标；群体笔记提供初始参考。群体经验不应覆盖个人的明确要求，一次购买行为也不足以确认稳定偏好。对于已过期或被用户修正的信息，还需要更新与失效机制。

我更关心的是一个闭环：用户表达或修改目标 → 更新笔记 → 调整计划 → 执行 → 根据结果核对进度。验证时可以重点看约束遗漏、重复执行，以及用户修改目标后是否真正改变了下一步行动。
